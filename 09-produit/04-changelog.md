### Changed
- **Onboarding switches to 3D renders.** Its two screens carried widget-drawn illustrations — detoured mascot, cards, category badges, search preview. Each now carries a full-frame render. Both source files arrived unusable: the mascot came out purple (247° and 234° against 224° in the app), a third-party logo was visible on one, and the original GIF of the first weighed 26 MB in 256 colours — its dark gradient reconstructed by a dot dither that flickers on OLED, and a loop that jumps, the gap between the last frame and the first being eight times a normal step. `tools/onboarding/build.py` undithers (blur comes **before** upscaling: after, the dots would be frozen in bigger pixels), brings the body back to the hue measured on `mascot.png` as the pose pipeline already does, rotates the red square's colour without touching its relief, crops the second scene — originally square — and **kills its backdrop** instead of rotating its hue, a sunset pushed towards blue turning green. Output: 1179 px wide, the exact width of a 3x screen, so zero upscaling on the device; 255 KB in WebP for both, against 1710 KB in PNG for the first alone. Images are static; everything that moves is painted on top: entrance motion, continuous breathing, parallax, and a light running across the ribbon. This light **is the image itself**, repainted in additive mode through a moving band: only already-bright pixels light up, the black sky stays black (0 + 0 = 0), and nothing can drift — where a manually-traced path would have floated beside the ribbon. The two fades cross on the painted sky and not on each other, otherwise two mascots overlap mid-gesture. `features/onboarding/mascot.dart` removed with its three components, no screen was displaying them. Both screens now open the submission captures, renumbered from 01 to 07: that is what a judge sees first on launching the app. Thirty-two golden renders instead of thirty — 2026-09-24.
- **Three mascot poses regenerated and matched** — puzzled, empty list, no search result. The pipeline was aligning the average hue to the reference, which let a spread gap through: the new renders dipped to cyan-green and the mascot's flank turned green. `tools/mascot/build.js` now compares the cold end of the gradient to the reference and brings it back. Second gap, inverse: hue aligned, **colour intensity** betrayed the poses — from 51 to 91% saturation across renders, `mascot.png` (the two onboarding screens) being the flattest. The tool now normalises them all to 80%, reference included. The six embedded poses hold within 2.5° of hue and come out at the same intensity. **Three others removed** (offline, reading, celebration): no screen was displaying them — 700 KB of assets gone — 2026-09-23.
- **Inter switches to the variable version**, and the interface breathes: one file instead of four (876 KB against 1.3 MB), the continuous `wght` axis and above all the `opsz` axis locked to text size — large headings tighten, small sizes open. Along the way: body line height to 1.5, and captions (domain, date, chips) in regular rather than medium, the secondary grey already carrying the visual step back. 25 golden renders regenerated — 2026-09-23.
- **A category path leads to lymarks, no longer to clusters.** Automatic grouping was never specified and clusters only existed in demo: the screen was showing a path that the real mode could not trace. Nodes are now the lymarks themselves. `KnowledgeCluster`, `Lymark.clusterId` and the Cluster screen removed — 2026-09-23.
- The mascot is frozen everywhere except onboarding: a floating character while reading a failure message draws the eye instead of accompanying it — 2026-09-23.
- Data access in raw SQL, Drizzle dropped (ADR-009) — 2026-09-18.
- V1.0 scope reduced to Android; iOS deferred to V1.1 (ADR-007) — 2026-09-17.

### Fixed
- **Without a network, the app stayed stuck on the launch screen** (observed on device in airplane mode). The Clerk SDK's `Auth.initialize()` **waits** for a first session token fetch, `sessionTokenPolling` being true by default; offline the request enters the SDK's retry mechanism — eight attempts with exponential delay — and `create` never returns. Yet this is the only `await` before `runApp`: Flutter was not drawing a single frame. Polling cut (the token is struck on demand) and retries brought from eight to three — 2026-09-23.
- The onboarding buttons said "Get started" then "Start saving": two promises, while the first only turns a page. It is "Next" then "Get started" — 2026-09-23.
- The splash flashed white: once the system splash screen was removed, `NormalTheme` held the window until the first Flutter frame with the theme background — white in light mode. All four variants switch to midnight blue — 2026-09-23.
- "Open original" opened the external browser instead of an overlay: since Android 11 an app only sees others if it declares them, and `url_launcher` concluded no tab existed. `<queries>` declares the Custom Tabs service — 2026-09-23.
- The detail card title was stacking vertically on a narrow column; it now takes the full width, capped at three lines — 2026-09-23.
- Golden renders were failing at random for several days: the demo set called `DateTime.now()` on each lymark, so two links "9 days ago" sometimes fell on the same millisecond and sometimes not, changing order between runs. Single reference instant, and a comparator that breaks ties on the identifier — `List.sort` is not stable in Dart — 2026-09-23.
- The paywall was switching the plan to Pro locally in real mode, bypassing the server; and a server refusal stays displayed in search instead of a silent "0 results" — 2026-09-19.
- Shell pages (JavaScript-loaded content) are classified as `blocked` instead of failed, and a preview agent is used for Instagram — 2026-09-19.
- No polling of processing cards while the app is offline: thirty pointless calls, observed on device — 2026-09-18.
